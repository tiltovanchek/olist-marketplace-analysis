# Словарь терминов

Краткие пояснения к отчёту и плану эксперимента. Точные числители, знаменатели и временные границы заданы в [словаре метрик](metrics.md), правила будущего теста — в [плане эксперимента](experiment_design.md).

## Исходный уровень метрики: baseline

**Baseline** — исходное значение метрики без новой инициативы. Для будущего теста это должна быть доля повторных покупателей в целевой аудитории при обычных уведомлениях и при тех же правилах расчёта, которые будут применены в эксперименте.

Сочетание «планировочный proxy baseline из conditional post-delivery метрики» означает: **«историческая доля повторных покупок после доставки как приближение для предварительного расчёта выборки»**.

Исторические 1,14% рассчитаны среди покупателей, получивших первый наблюдаемый заказ, с корректной датой доставки и полным 90-дневным окном. Их первая покупка относится к сервисному периоду: с 1 января 2017 года по 30 июня 2018 года. Слово **conditional** означает условие отбора: в расчёт входят только такие покупатели. **Post-delivery** означает отсчёт после получения заказа, **proxy** — приближение, которым временно заменяется ещё не измеренное нужное значение.

Эти 1,14% подходят для иллюстрации расчёта выборки. Их нельзя считать точным исходным уровнем будущего теста: в его аудитории будут покупатели с риском задержки, включая тех, кто затем не получит опорный заказ в установленный срок.

## Аудитория риска и наблюдение: high-risk ITT shadow cohort

Фраза «оценить baseline на high-risk ITT shadow cohort» означает: **«до запуска измерить исходную метрику у аудитории с риском задержки, отобранной по будущим правилам теста, пока без нового уведомления»**.

- **High-risk** — высокий риск задержки, определённый по информации, доступной на момент включения. Фактическое будущее опоздание для отбора использовать нельзя.
- **Eligibility** — заранее установленные правила включения покупателя в тест.
- **Shadow cohort** — наблюдательная группа с теми же правилами отбора и расчёта метрик, что и в будущем тесте, но без новой инициативы. Такой режим позволяет проверить численность аудитории, регистрацию событий и исходную метрику. Он сам по себе не заменяет рандомизированное сравнение.
- **ITT, intention-to-treat** — анализ всех изначально назначенных участников в исходных группах, независимо от получения сообщения, отмены или доставки заказа. В предварительном режиме наблюдения нужно воспроизвести будущий знаменатель: учитывать всех отобранных покупателей. Само наблюдение ещё не является ITT-оценкой экспериментального эффекта, поскольку случайного назначения инициативы не было.

В плане проекта успех требует получения опорного заказа в первые 60 дней и подходящей повторной покупки в следующие 90 дней после получения. Максимальный горизонт покупки — 60 + 90 = 150 дней от включения. Если опорный заказ не получен за 60 дней, участник остаётся в знаменателе с исходом 0. Доставка повторного заказа подтверждается по заранее заданному правилу, для чего может потребоваться дополнительное время после окна покупки.

## Fanout — размножение строк при соединении

**Fanout** — увеличение числа строк при соединении таблиц, в каждой из которых одному ключу соответствует несколько записей. Из-за этого одни и те же деньги могут суммироваться несколько раз.

Например, у заказа две позиции стоимостью 100 и 50 R$ и три платежа по 50 R$. Если напрямую соединить позиции и платежи по `order_id`, получится **2 × 3 = 6 строк**. Каждая позиция повторится три раза: сумма цен ошибочно вырастет со 150 до 450 R$. Каждый платёж повторится два раза: сумма платежей вырастет со 150 до 300 R$.

В проекте позиции и платежи сначала суммируются отдельно до одной строки на заказ. Затем обе итоговые таблицы соединяются с заказами. Так GMV и платежи сохраняют исходные значения.

## Другие сокращения

| Термин | Значение в проекте |
|---|---|
| GMV | Стоимость товаров в доставленных заказах без доставки. Выручка платформы по этим данным неизвестна |
| AOV | Средний чек: GMV / число доставленных заказов |
| BRL, R$ | Бразильский реал и его обозначение |
| Опорный заказ, index order | Заказ, от которого ведётся отсчёт. В историческом анализе — первая наблюдаемая доставленная покупка; в будущем тесте — первый заказ, соответствующий правилам риска в период набора |
| Полное окно, зрелость | С момента начала отсчёта до конца наблюдения прошло достаточно времени для расчёта метрики. Это не гарантирует полноту исходной выгрузки |
| Retention M1–M6 | Доля покупателей когорты с доставленной покупкой в соответствующем календарном месяце после месяца первой наблюдаемой покупки |
| П.п. | Процентный пункт. Изменение с 1% до 1,5% — +0,5 п.п. и +50% относительно исходного уровня |
| CI | Доверительный интервал, показывающий неопределённость оценки при выбранном статистическом методе |
| Ассоциация | Наблюдаемая связь признаков. Различие оценок у поздних и своевременных заказов ещё не показывает, как изменятся оценки после устранения задержек |
| Кластерный бутстрап | Повторная случайная выборка покупателей с сохранением всех заказов каждого выбранного покупателя |
| Seed | Начальное значение генератора случайных чисел для повторяемости расчёта |
| MDE | Минимальное изменение, на обнаружение которого рассчитан размер выборки при заданных уровне значимости и мощности |
| Guardrails | Защитные метрики: ограничения на побочные последствия, например рост жалоб или стоимости |
| SRM | Проверка, соответствует ли численность экспериментальных групп ожидаемому распределению, например 1:1 |
| Cutoff | Фиксированная граница наблюдения. В анализе события покупки ограничены условием `purchase_ts < 2018-09-01` |
